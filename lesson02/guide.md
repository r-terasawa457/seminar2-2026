# 演習2 ガイド：GitHub のコードを Colab で動かす

ノートブック `02_run_github_code.ipynb` と一緒に使うガイドです。ノートブックは手順の「型」、このガイドはその手順の中で判断に迷うところの説明です。

研究では、論文の著者が公開したコードを動かし、自分のデータで試し、少しずつ直していくところから始めることがよくあります。今回の目標は、知らないリポジトリでも「README を読んで、必要なものをそろえ、公式の例を動かす」までを自力でできるようになることです。うまく動かなかったときも、どこまで進んで何が起きたかを記録すれば、それも成果です。

## 1. リポジトリを選ぶ

最初の1つは、次の条件をなるべく満たすものを選ぶと、つまずきにくくなります。

| 確かめること | 見る場所 | 目安 |
| --- | --- | --- |
| 推論（学習済みモデルで予測する）の例がある | README の Usage、Inference、Demo、Quick Start | コマンド1行、またはコード数行で動かせる |
| 学習済みの重みが公開されている | README の Pre-trained Models、Checkpoints、Model Zoo | HF Hub や Google Drive のリンクがある |
| 重みの大きさが Colab の GPU に収まる | 重みの表、モデルカード | パラメータ数が数億（数百 M）まで。数十億（数 B）を超えると、T4（VRAM 16GB）では工夫が必要 |
| Python と PyTorch の版の条件が Colab と合う | README の Requirements、`pyproject.toml`、`setup.py` | 古すぎる版（Python 3.8 のみ、PyTorch 1.x のみなど）を指定していない |
| 最近まで手入れされている | ファイル一覧の上の最終更新日、Issues | 数年前で止まっていると、ライブラリの版が合わないことが多い |
| ライセンス | `LICENSE`、モデルカード | 授業や研究で使う範囲で問題ないか。重みはコードと別のライセンスのことがある |

探し方の例：

- 気になったモデルの論文やプロジェクトページから、"Code" や GitHub のリンクをたどる。
- [Papers with Code](https://paperswithcode.com/) の後継のサービスや、HF Hub のモデルページ（"Use this model"）からリポジトリを探す。
- README に Colab のバッジ（"Open in Colab"）があれば、まずそれを動かすのも手です。ただし、このノートブックの型で自分で組み立て直すと、何をしているかがわかるようになります。

**最初の1つにはおすすめしないもの**：学習（training）しか書かれていないもの、重みを申請してから数日待つもの、独自の CUDA 拡張のビルド（`python setup.py build_ext` など）が必要なもの、Docker 前提のもの。

## 2. README を読む

README は上から全部読む必要はありません。次の5つを探します。

1. **動作環境**：Python、PyTorch、CUDA の版。ノートブックの 1. で表示した版と比べます。
2. **インストール**：`pip install -r requirements.txt` か、`pip install -e .` か。
3. **学習済みの重み**：どこから取って、どのフォルダに、どのファイル名で置くか。
4. **使い方**：推論のコマンドと、その引数。引数の初期値も確かめます（記入例の `run.py` は、何も指定しないと一番大きい Large を使います）。
5. **ライセンス**。

英語の README は、わからない部分を翻訳しながら読んでかまいません。ただしコマンドやファイル名は、翻訳せずにそのまま写します。

## 3. README のコマンドを Colab で実行する

| README の書き方 | Colab のセル | 理由 |
| --- | --- | --- |
| `git clone ...`、`python run.py ...` | `!git clone ...`、`!python run.py ...` | `!` を付けると、端末のコマンドとして実行される |
| `cd フォルダ` | `%cd フォルダ` | `!cd` は、その1行の中でしか効かない |
| `pip install ...` | `%pip install ...` | ノートブックが使っている Python に確実に入る |
| `conda create ...`、`conda activate ...` | 使わない | Colab には conda がない。`pip` で入れる |
| `export VAR=...` | `%env VAR=...` か `os.environ["VAR"] = "..."` | `!export` は、その1行の中でしか効かない |
| 行末の `\`（コマンドの続き） | そのまま書くか、1行にまとめる | |
| `python app.py`（Gradio の Web デモ） | `!python app.py` で起動し、表示される URL を開く | 止めるには、セルの停止ボタンを押す |

`!` の行では、`{変数名}` と書くと Python の変数の値が埋め込まれます。

## 4. 依存ライブラリを入れる

- **torch と torchvision は、ふつう入れ直さない**：`requirements.txt` に `torch==2.0.1` のような指定があっても、Colab に入っている版のまま動くことが多いです。入れ直すと、GPU（CUDA）との組み合わせが崩れて動かなくなることがあります。まず外して試し、動かなかったときに版を合わせることを考えます。
- **使わないものは外す**：Web デモ用の `gradio`、学習用の `wandb`、`tensorboard` などは、推論だけなら不要なことがあります。
- インストールの後に「セッションを再起動」の案内が出たら、再起動して 1. から実行し直します。入れたライブラリは、接続が切れるまで残ります。

## 5. 変更を残す

Colab の接続が切れると、取得したリポジトリや、直したコードは消えます。ノートブック自体（文章、コード、出力）は、ドライブに保存したコピーに残ります。

| 方法 | よいところ | 気をつけるところ |
| --- | --- | --- |
| **(a) 変更をパッチとして保存する**（ノートブックの 9.。おすすめ） | 小さなテキストファイル1つで済む。元のリポジトリから何を変えたかが一目でわかる。再開したら `git apply` で当て直せる | 毎回 clone とインストールをやり直す（数分）。パッチは `REPO_REF` の版に対する差分。初回にドライブの許可が要る（下の注意） |
| (b) リポジトリごと Google ドライブに置く | 直したファイルが、そのまま残る | 初回にドライブの許可が要る（下の注意）。ドライブ上はファイルの読み書きが遅い。重みを置くと容量（無料は 15GB）を使う。インストールしたライブラリは結局消える |
| (c) VS Code から Colab を使う（Google の「Colab」拡張機能） | ノートブックとコードが自分の PC にあり、使い慣れたエディタで直せる | 計算する側（Colab のサーバー）のファイルは一時的なのは同じ。拡張機能の機能は更新が速いので、使う前に公式の説明を確かめる |

**ドライブの許可について**：(a) と (b) は、Colab からドライブをつなぎます（`drive.mount`）。初回に表示される許可の画面には、ドライブのほかに、Google フォト、連絡先やプロフィールなど、多くの項目が並びます。これは Colab がドライブをつなぐ仕組みの都合で、一部の項目だけを選ぶと、つながらずにエラーになります。**すべて選択**して続けてください。

どの方法でも、**動いた版（コミット）と、何を変えたか**を記録しておくことが大事です。研究でも、どの版のコードで出した結果かがわからないと、再現できなくなります。

## 6. つまずいたとき

エラーが出たら、まず**一番最後の行**を読みます。そこに、何が起きたかが書いてあります（上のほうは、どこを通ってそこに着いたかの記録です）。

| エラーや症状 | よくある原因 | 対処 |
| --- | --- | --- |
| `ModuleNotFoundError: No module named 'xxx'` | ライブラリを入れていない。またはリポジトリの中の `.py` が見つからない | 4. で入れ忘れていないか確かめる。リポジトリ内のモジュールなら、`%cd` でリポジトリに入っているか、`sys.path` に入っているかを確かめる |
| `FileNotFoundError: checkpoints/...` | 重みを置いていない、置き場所やファイル名が違う | README の指示と、5. の `WEIGHTS_DIR` を比べる。`!ls checkpoints` で中身を見る |
| `401 Unauthorized`、`403`、`GatedRepoError` | ゲート付きの重みで、申請していない、承認前、トークンがない | HF で申請し、承認を待つ。トークンを Colab のシークレット `HF_TOKEN` に登録し、ノートブックからのアクセスをオンにする |
| `CUDA out of memory` | モデルや入力が GPU のメモリに収まらない | 小さいモデルにする。入力の画像を小さくする。バッチを1にする。「ランタイム」→「セッションを再起動」で、たまったメモリを空ける |
| `bfloat16` を含むエラー、極端に遅い | T4 は bfloat16 に対応していない（例のコードは `torch.bfloat16` が多い） | `torch.bfloat16` を `torch.float16` に変える。結果がおかしいときは `torch.float32` にする（メモリは2倍使う） |
| `Torch not compiled with CUDA enabled`、`no kernel image is available` | torch を入れ直して、GPU と合わない版になった | 「ランタイム」→「ランタイムを接続解除して削除」で環境を初期化し、torch を外して入れ直す |
| `requires a different Python: 3.x` | リポジトリが指定する Python の版と合わない | 条件が緩められないか README や Issues を探す。無理なら、別のリポジトリか、HF Transformers に入っている同じモデルを使う |
| `cv2.imshow` で止まる、画像が出ない | Colab には画面のウィンドウがない | `from google.colab.patches import cv2_imshow` の `cv2_imshow(img)` か、matplotlib で表示する |
| 重みのダウンロードが進まない（0 バイトのまま） | HF Hub の新しい転送方式（Xet）で止まることがある | セルの最初で `import os; os.environ["HF_HUB_DISABLE_XET"] = "1"` としてから、取得し直す |
| `NameError` | 前のセルを実行していない。接続が切れた | 1. から順に実行し直す |
| `MessageError: Error: credential propagation was unsuccessful`（ドライブをつなぐとき） | 許可の画面で、一部の項目だけを選んだ。Colab にログインしているアカウントと、許可したアカウントが違う | セルを実行し直し、許可の画面で Colab と同じアカウントを選んで、**すべて選択**する |
| `git apply` で `patch does not apply` | パッチを作ったときと、リポジトリの版が違う | 2. の `REPO_REF` を、パッチを作ったときの版に戻す |

調べるときは、エラーの最後の行をそのまま検索するか、リポジトリの Issues で検索します。同じところでつまずいた人が、解決法を書いていることがよくあります。生成 AI に聞くときは、エラーの全文と、何をしようとしていたか（リポジトリ、実行したセル）を一緒に渡すと、的外れな答えが減ります。

## 7. 記入例2：SAM3（ゲート付きの例）

SAM3（Meta の Segment Anything Model 3）は、「黄色いスクールバス」のような文字で指定した対象を、画像や動画から切り抜けるモデルです。重みがゲート付きなど、記入例の Depth Anything V2 よりつまずきどころが多い例です。

> この節は README とモデルカードを読んで書いた手順です。Colab での動作はまだ確かめていません。

| 手順 | 書き換える値、やること |
| --- | --- |
| 2. リポジトリ | `REPO_URL = "https://github.com/facebookresearch/sam3.git"` |
| 1. と比べる | README の条件は Python 3.12 以上、PyTorch 2.7 以上、CUDA 12.6 以上 |
| 4. インストール | パッケージとして入れる形なので、`%pip install -e .`（例のノートブックを動かすなら `%pip install -e ".[notebooks]"`） |
| 5. 重み | HF Hub の `facebook/sam3` で利用を申請し、承認後にトークンを `HF_TOKEN` に登録する |
| 6. 公式の例 | `examples/sam3_image_predictor_example.ipynb` のセルを、順に写して動かす |
| 注意 | 例のコードが `torch.bfloat16` を使っていたら、T4 では `torch.float16` に変える |
| ライセンス | SAM License（モデルカードと `LICENSE` を読む） |

## 8. ライセンスと使い方の注意

- コードと重みのライセンスは別々のことがあります。記入例の Depth Anything V2 は、コードと Small の重みが Apache-2.0、Base と Large の重みが CC BY-NC 4.0（非商用）です。
- 人の顔や声を扱うモデル（顔の入れ替え、声の複製など）は、本人の同意なしに使わないでください。自分の写真や声、または利用が許されたデータで試します。
- HF のトークンや API キーは、パスワードと同じです。セルに直接書いたり、ノートブックやパッチと一緒に共有したりしないでください。
